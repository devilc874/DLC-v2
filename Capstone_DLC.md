# Capstone Project: DLC v2 — Delta-Linear Compression Engine for High-Frequency Time-Series Data

---

## 1. Abstract

High-frequency time-series data generated by IoT sensors, industrial monitoring systems, and cloud infrastructure produces massive volumes of IEEE 754 double-precision floating-point values. Conventional general-purpose compressors such as GZIP and ZLIB rely on LZ77 dictionary-based methods that search for repeating byte patterns. However, the lower 40 bits of a float64 mantissa contain thermal noise — effectively random bytes — which defeats byte-level pattern matching entirely. This phenomenon, termed the **"Entropy Trap,"** renders traditional compressors ineffective on floating-point sensor data, yielding compression ratios near 1.0x.

This project proposes **DLC v2 (Delta-Linear Compression)**, a domain-specific, near-lossless compression engine that operates in the mathematical domain rather than the byte domain. DLC fits predictive models (Linear, Quadratic, XOR-Delta, Constant, Sinusoidal, and Predictive XOR) to adaptive signal windows, computes small residuals, quantizes them with adaptive precision (8-20 bits per window), and entropy-encodes the resulting integer distributions using six competing strategies -- selecting the smallest encoding per window. Additionally, a **block-level Delta-of-Delta (DoD) fast path** evaluates encoding entire blocks as a single Constant(mean) window with DoD encoding, eliminating per-window metadata overhead when beneficial. The quantized residuals follow a Laplacian distribution (peaked at zero), enabling extreme compression that byte-level methods cannot achieve.

The engine is implemented as a **dual-architecture system**: a Python prototype for rapid algorithm development and verification, and a C++17 production engine for high-throughput parallel compression. Both engines produce identical binary output, ensuring cross-language compatibility. The binary `.dlc` format features a 64-byte header, per-window metadata with adaptive precision, zlib post-compression, and CRC-32 integrity verification. **Precision is user-configurable** via the `--precision` CLI flag (default 16-bit), allowing users to trade accuracy for compression ratio -- from near-lossless (20-bit) to aggressive lossy (8-bit).

Benchmarking across 25+ datasets -- including synthetic waveforms, AWS EC2 telemetry, NYC taxi demand, 420,000-point Jena Climate records, and 3M-sample industrial sensor simulations -- demonstrates that DLC v2 achieves **80% win rate** against five industry-standard techniques (Gorilla, Delta-of-Delta, RLE, GZIP, ZLIB) when evaluated at equal precision. The engine maintains a strict per-sample reconstruction error bound of less than 8x10^-6 at 16-bit precision. An interactive Streamlit-based dashboard provides real-time compression analysis, industry comparison with error analysis, and fair 16-bit evaluation.

## 2. Project Objectives (Team)

### Objective 1: Design and Implement a Multi-Model Predictive Compression Pipeline

Develop a five-stage compression pipeline consisting of block chunking, adaptive variance-guided windowing, multi-model selection, residual encoding, and binary assembly with zlib post-compression. The pipeline supports six predictive models -- Linear Regression, Quadratic Regression, XOR-Delta, Constant, Sinusoidal (FFT + Gauss-Newton), and Predictive XOR -- with automatic model selection based on Sum of Squared Residuals (SSR) minimization. The system implements six encoding strategies (Zigzag-Varint, Fixed-Width Bitpack, Delta-of-Residuals, MAD Outlier Separation, RLE, and Delta-of-Delta) with trial-based selection to minimize encoded output size per window. A block-level DoD fast path evaluates encoding entire blocks as a single Constant(mean) window with DoD encoding to eliminate metadata overhead.

### Objective 2: Develop a High-Performance C++17 Production Engine with True Parallelism

Port the complete compression and decompression pipeline from Python to C++17, utilizing true multithreaded parallelism via `std::thread` and `std::future` to overcome the Python Global Interpreter Lock (GIL) bottleneck. The C++ engine will achieve throughput scaling proportional to available CPU cores on large datasets while producing bit-for-bit identical output to the Python prototype, ensuring cross-language interoperability and round-trip verification.

### Objective 3: Define a Cross-Platform Binary File Format with Integrity Verification

Design and implement a custom `.dlc` binary file format featuring a 64-byte header (magic bytes, versioning, precision, sample count), per-window block metadata (model ID, encoding ID, adaptive precision bits), zlib-compressed payload, and an 8-byte footer with CRC-32 checksum of the uncompressed payload. The format will be fully little-endian for cross-platform compatibility and will support forward extensibility through reserved header fields.

### Objective 4: Benchmark Against Industry Standards, Validate Error Bounds, and Visualize

Conduct comprehensive benchmarking against **five industry-standard compression techniques** -- Gorilla (Facebook TSDB), Delta-of-Delta (InfluxDB/Prometheus), Run-Length Encoding, GZIP, and ZLIB -- across 25+ datasets including synthetic waveforms, real-world AWS telemetry, NYC taxi demand data, 420,000-point climate records, and 3M-sample industrial sensor simulations. Implement **round-trip error analysis** proving DLC maintains <8x10^-6 error while DoD has ~1.2x10^-4 error (17x worse). Provide a **fair 16-bit equal-precision evaluation** where DLC achieves an 80% win rate. Develop automated benchmark scripts, an interactive Streamlit web dashboard with error tables and fair comparison views, and presentation-quality visualizations.

## 3. Individual Project Objectives (Team Member Contributions)

### Team Member 1: Adaptive Block Dispatch and Variance-Guided Segmentation

**Module Summary:** Responsible for the first two stages of the compression pipeline — partitioning the raw float64 stream into fixed blocks for parallel dispatch, and segmenting each block into statistically homogeneous windows using a variance-guided algorithm.

- **Contribution to Objective 1 (Block Chunking):** Partition the float64 stream into fixed 100,000-sample blocks for parallel dispatch. Workers may finish in any order; outputs are reassembled in deterministic block-index order using an index-keyed reassembly buffer, ensuring byte-identical compressed output regardless of thread count or completion order.
- **Contribution to Objective 1 (Variance-Guided Windowing):** Implement the adaptive segmentation algorithm using Welford's (1962) single-pass numerically-stable variance update — avoiding catastrophic cancellation in the textbook `E[x²] − E[x]²` formula on large sensor values that are close together. Window sizes grow via greedy doubling search (16 → 32 → 64 → …) with binary refinement while `σ²(W) ≤ T = max(σ²_init·10, σ²_global·0.10)`, capped at 4,096 samples. A stagnation guard aborts expansion on variance jumps > 1.5×.
- **Contribution to Objective 1 (Constant Fast Path):** Implement a constant-region fast path that emits the entire block as a single window when `σ²_global < 10⁻²⁰`, providing a cheap escape hatch for genuinely flat signal regions.
- **Contribution to Objective 2:** Port the windowing algorithm and block dispatch logic to C++17 with identical segmentation behavior. Implement the deterministic dispatch contract in C++ using `std::async` with index-keyed ordering.

### Team Member 2: Entropy Tournament and Adaptive Precision Controller

**Module Summary:** Responsible for the residual encoding stage — designing and implementing the six competing encoding strategies, the trial-encode tournament mechanism, and the adaptive per-window precision controller that enforces the strict error bound.

- **Contribution to Objective 1 (Encoding Strategies):** Implement all six residual encoding strategies, trial-encoded in parallel per window — Zigzag-Varint, Fixed-Width Bitpack, Delta-of-Residuals, MAD Outlier Separation (tuned MAD factor of 4.5 with complete encoder/decoder), Run-Length Encoding, and Delta-of-Delta. The smallest byte string wins the tournament. Including Delta-of-Delta makes DLC a strict superset of the InfluxDB/Prometheus timestamp encoder (DoD-superset claim verified empirically: DoD wins on 18 of 21 datasets in the benchmark suite).
- **Contribution to Objective 1 (Adaptive Precision):** Design and implement the adaptive precision controller (8–20 bits per window). Per-window precision floats with a strict floor of `p_floor = 16`, enforcing `|error| ≤ 8 × 10⁻⁶`. Smooth windows may drop to 8 bits while noisy windows pay the full 16-bit cost. Precision floor derivation: `max_err = 2⁻¹⁷ ≈ 7.6 × 10⁻⁶` at 16-bit precision, rounded up to `8 × 10⁻⁶` as the conservative contract.
- **Contribution to Objective 1 (XOR Encoding):** Develop XOR residual encoding with optional delta-of-XOR compression for XOR-based models (XOR-Delta and Pred-XOR).
- **Contribution to Objective 2:** Port all encoding strategies, quantization, dequantization, and adaptive precision selection to C++17 with byte-identical output. Cross-language byte equivalence verified: Python and C++ entropy outputs are byte-identical for every strategy on closed-form residuals.
- **Contribution to Objective 4:** Measure encoding strategy selection frequency and per-strategy compression efficiency across datasets.

### Team Member 3: Predictive Models and SSR-Based Selector

**Module Summary:** Responsible for designing and implementing the six predictive models that capture the mathematical structure of each signal window, and the SSR-based model selector that chooses the optimal model per window.

- **Contribution to Objective 1 (Six Predictive Models):** Design and implement six predictive models, fitted in parallel per window — Linear Regression (closed-form least squares), Quadratic Regression (Cramer's rule on a 3×3 normal equation system), XOR-Delta (lossless bitwise float64 XOR), Constant (mean-based, 1 parameter), Sinusoidal (FFT-seeded Levenberg–Marquardt / Gauss-Newton refinement with 4 parameters: A, ω, φ, dc), and Predictive-XOR (lossless linear extrapolation predictor with 2 anchors).
- **Contribution to Objective 1 (SSR-Based Selector):** Implement the model selector using Sum-of-Squared-Residuals (SSR) minimization with tie-break rules. Minimum SSR wins; ties within 1% favor (a) the simpler model (fewer parameters) and (b) the lossless variant (XOR-based). Empirical validation: SSR-best model agrees with size-best model on all 21 benchmark datasets.
- **Contribution to Objective 1 (Edge Case Routing):** Implement NaN / ±Inf / subnormal detection at window scan; XOR-Delta is forced for those windows since it is the only safe lossless option that handles non-finite IEEE 754 values.
- **Contribution to Objective 2:** Port all six model implementations to C++17 — including a custom O(n) Discrete Fourier Transform for sinusoidal frequency estimation and a 4×4 Gaussian elimination solver for Gauss-Newton optimization, without external dependencies (no FFTW, no LAPACK). Five models are closed-form and produce byte-identical output across Python and C++; Sinusoidal is iterative and guarantees cross-decode within the error envelope.
- **Contribution to Objective 3:** Define the model parameter storage format within window blocks (variable-length based on model ID: 1–4 parameters per model).
- **Contribution to Objective 4:** Analyze per-model selection frequency across datasets to validate that all models are being selected where appropriate and improving compression ratios.

- SSD is recommended because benchmark scripts perform repeated file I/O; HDD latency would skew throughput measurements.
